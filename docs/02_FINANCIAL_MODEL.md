# Финансовая Модель Seller CFO (Single Source of Truth)

Настоящий документ описывает математическую и архитектурную основу расчетов в системе Seller CFO для Wildberries и Ozon. Любое отклонение от данных формул приведет к искажению налоговой и управленческой отчетности.

## 1. REVENUE (Налогооблагаемая Выручка, База УСН)
- **Определение:** Общая сумма, уплаченная покупателем, признаваемая доходом селлера до вычета комиссий.
- **Wildberries:** Поле `retail_price_withdisc_rub` из `POST /api/finance/v1/sales-reports/detailed`. (Внимание: Скидка постоянного покупателя СПП компенсируется за счет маркетплейса и НЕ уменьшает налоговую базу).
- **Ozon:** Итоговая цена продажи из Отчета о реализации (`POST /v2/finance/realization`).
- *Применение:* С этой суммы рассчитывается налог УСН (6% или 15%).

## 2. MARKETPLACE COSTS (Агрегированные издержки платформы)
- **Определение:** Сумма всех неденежных удержаний маркетплейса, удерживаемых до перечисления выручки.
- **Wildberries:** 
  - Комиссия: `ppvz_vw` + `ppvz_vw_nds`
  - Эквайринг: `acquiring_fee`
  - Логистика: `delivery_rub`
  - Хранение: данные из `GET /api/v1/paid_storage`
  - Штрафы: `antifraud`, `deductions` и штрафы за габариты `measurement-penalties`.
- **Ozon:** Сумма всех транзакций типа Комиссия, Услуги логистики, Хранение из `POST /v3/finance/transaction/list`.

## 3. ACCRUALS / PAYABLE (К перечислению / Accounts Receivable)
- **Определение:** Сумма, которую маркетплейс физически переведет на расчетный счет продавца.
- **Формула:** `REVENUE - MARKETPLACE COSTS`
- **Кросс-чек (Валидация API):** Эта расчетная сумма ОБЯЗАНА сходиться до копейки с полем `ppvz_for_pay` (на WB) и `accruals_for_sale` (на Ozon). Расхождения вызывают Alert.

## 4. COGS & INVENTORY VALUE (Себестоимость)
- **Определение:** Балансовая стоимость проданного товара.
- **Источник:** ИСКЛЮЧИТЕЛЬНО база данных Seller CFO (ручной ввод продавцом или импорт). Маркетплейсы эту информацию по API не отдают. 
- **Формула:** `Input(Unit_COGS) * Quantity_Sold`.

## 5. PROFIT & MARGIN (Чистая прибыль и Маржинальность)
- **Contribution Margin (на уровне 1 SKU):** `retail_price_withdisc_rub` − `COGS_Unit` − (Комиссии + Логистика) − (`retail_price_withdisc_rub` * Tax_Rate).
- **Operating Profit:** `ACCRUALS` - `COGS` - Специфичные расходы на рекламу (Performance API).
- **Net Profit (Чистая прибыль):** `Operating Profit` - `Input(External OpEx)` - `TAXES`.
- **Margin (Рентабельность):** `(Net Profit / REVENUE) * 100%`.

## 6. CASH FLOW & WORKING CAPITAL (ДДС)
- **Определение:** Движение реальных денег. В Cash Flow игнорируются все `MARKETPLACE COSTS`, так как они являются неденежным взаимозачетом. Учитывается только итоговый PAYOUT.
- **Формула Cash-In:** Фактические поступления по банку, сверяемые с балансовыми методами.
- **Working Capital:** `Cash` + `Accounts Receivable` (Невыплаченные суммы маркетплейса) + `Inventory Value` (Стоимость остатков по COGS) - `Accounts Payable` (Долги поставщикам).

## 7. Immutable Ledger (Архитектура БД)
Для предотвращения проблем с изменениями отчетов задним числом:
- Каждая строка из финансового API записывается в БД и блокируется для изменений.
- Если площадка делает корректировку, она присылает отдельную строку с отрицательным или положительным значением (Сторно). Эта строка добавляется в Ledger, суммы схлопываются математически по `srid`.
